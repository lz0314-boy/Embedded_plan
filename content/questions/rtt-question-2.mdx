## 参考回答

信号量主要表达“可用资源或事件计数”，可以由一个线程释放、另一个线程获取；互斥量表达“临界资源所有权”，通常要求持有者解锁，并可能提供优先级继承来缓解优先级反转。二者都可以设置阻塞超时，但超时返回不等于获得了资源，调用方必须检查返回值并记录等待对象。

选择时先问清楚是否有所有权和递归加锁需求：保护共享结构时优先考虑互斥量；传递计数或同步生产/消费时考虑信号量、消息队列或事件。ISR 能否调用、可用的 API 变体、调度锁和内存分配限制必须查目标 RT-Thread 版本的 IPC 文档和源码，不能把线程 API 直接放进中断。

## 评分点

- 能区分资源计数/事件与互斥所有权。
- 能解释优先级继承、阻塞超时和超时后的错误处理。
- 能说明 ISR 调用限制以及版本、配置和端口边界。

## 递进追问

1. 三个线程以不同优先级争用同一资源时，如何用日志确认是优先级反转而不是锁泄漏？
2. 生产者比消费者快时，信号量计数和消息队列载荷分别解决什么问题？

## 证据边界

概念和 API 以 RT-Thread v5.2.2 线程/IPC 文档及对应 `ipc.c` commit 为准；具体 ISR 可调用列表、优先级继承配置和端口临界区仍需按工程配置核验。
