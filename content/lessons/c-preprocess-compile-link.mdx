## 一句话结论

头文件解决声明共享，源文件产生独立翻译单元，链接器解析外部符号并按规则布局段；宏错误、重复定义、未定义引用和镜像布局问题必须在对应阶段定位。

## 适用范围与前置知识

- 适用：C99 翻译单元、宏、声明/定义、内部/外部链接，以及 GCC + GNU ld 常见工作流。
- 不适用：把某份链接脚本的 Flash/RAM 地址复制到 STM32F103C8T6 或其他板卡。
- 前置：函数、全局对象、数组、指针和基本命令行使用。

## 从源文件到镜像

```mermaid
flowchart LR
  A[source.c + headers] --> B[预处理结果 .i]
  B --> C[编译/汇编得到 .o]
  C --> D[符号与重定位]
  D --> E[链接器 + 库 + 链接脚本]
  E --> F[ELF/映像]
  F --> G[加载器或烧录工具]
```

文字降级：头文件被包含并展开，源文件成为翻译单元；编译器生成目标文件；链接器解析符号和重定位，再按照默认规则或链接脚本生成 ELF/镜像；如何加载或烧录属于具体平台。

## 四类常见问题

| 现象 | 主要阶段 | 首要证据 | 常见根因 |
| --- | --- | --- | --- |
| 宏展开后语法异常 | 预处理 | `-E` 输出 | 参数多次求值、缺括号、条件宏不同 |
| 类型不匹配/隐式声明 | 编译 | 告警与翻译单元 | 头文件声明缺失或不一致 |
| `multiple definition` | 链接 | 符号表与链接命令 | 在头文件放了外部定义 |
| `undefined reference` | 链接 | 链接顺序、库和符号 | 未链接目标文件、条件编译移除实现 |

## static、extern 与声明/定义

文件作用域 `static` 名字具有内部链接，只在该翻译单元内参与名字绑定；`extern` 通常声明一个在别处定义的外部链接对象或函数。函数内 `static` 对象具有静态存储期，但名字仍是块作用域。“作用域、存储期、链接属性”是三件不同的事。

```c
/* counter.h */
#ifndef COUNTER_H
#define COUNTER_H
extern unsigned long counter_value;
void counter_increment(void);
#endif

/* counter.c */
#include "counter.h"
unsigned long counter_value;
static unsigned long increment_step = 1UL;

void counter_increment(void)
{
    counter_value += increment_step;
}
```

头文件放声明，恰好一个源文件放外部定义。头文件保护防止同一翻译单元重复包含，不会自动修复跨翻译单元的重复外部定义。

## 宏的反例与替代

```c
#define SQUARE_BAD(x) x * x
#define MAX_BAD(a, b) ((a) > (b) ? (a) : (b))

static int square_int(int value)
{
    return value * value;
}
```

`SQUARE_BAD(1 + 2)` 因缺少整体和参数括号而改变含义；`MAX_BAD(i++, j++)` 可能多次求值参数。能用类型明确的函数表达时优先使用函数；必须用宏时限制副作用并检查预处理结果。

## 调试步骤

1. 保存完整编译和链接命令，不只保存 IDE 截图。
2. 用 `gcc -E` 检查条件编译和宏展开；用 `gcc -c` 把编译问题与链接问题拆开。
3. 用 `nm`、`readelf -s` 查看符号的定义、未定义状态和绑定；用 map 文件查看实际段布局。
4. 嵌入式镜像继续核对目标链接脚本、启动文件、内存手册和烧录产物，未运行则记录为 `not-run`。

以上命令是 GNU 工具链工作流示例，本课没有在用户目标工具链中实际执行。

## 反例

- 在头文件直接写 `int state = 0;`，再用 include guard 解释为什么不会重复定义。
- 只看到编译生成 `.o` 就断言最终镜像可启动。
- 用主机默认链接脚本推断 MCU 的向量表地址、栈顶或 Flash 分区。

## 30 秒回答

预处理负责包含、宏和条件编译；每个 `.c` 独立编译成目标文件；链接器解析外部符号和重定位并生成镜像。`static`、`extern` 要分别从作用域、存储期和链接属性回答，嵌入式段地址必须查目标链接脚本和芯片资料。

## 展开回答

遇到问题先按阶段切开：宏异常看预处理结果，类型错误看单个翻译单元，符号错误看链接命令和符号表，运行前崩溃再看入口、段拷贝/清零和加载地址。头文件应提供一致声明，外部对象只保留一个定义；链接脚本属于工具链和平台实现，不是 ISO C 语义。
